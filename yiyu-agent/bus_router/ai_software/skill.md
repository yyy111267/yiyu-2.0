# ai_software · AI 软件/大模型 · 解读手册

> **适用范围**：以大模型 API、企业 AI 软件订阅/按量计费为主要商业模式的公司。通常处于研发期或商业化验证阶段，当期亏损，价值在未来现金流期权。
> **禁用场景**：纯消费硬件公司；公司已连续 4 季盈利且 OCF > 0（此时评估是否应切换至 consumer_brand）。
> **来源**：G4（平台/网络效应）+ G5（未盈利成长 overlay）合并（2026-08-24）。
> **配合使用**：指标字典 v1.0；Core Skill（7维母框架，固定加载）。

---

## 一、这门生意靠什么赚钱

**一句话本质**：烧钱换增长、赌未来单位经济转正的期权型生意——当期不赚钱，价值来自「如果规模效应兑现」的未来现金流期权。

**两层判断**（先判断第一层，再看第二层）：

**第一层：生意模式是否真实（护城河来源）**

| 问题 | 真正的 AI 软件生意 | 伪 AI 生意 |
|------|-----------------|-----------|
| 护城河来源 | 算法/数据/生态锁定（用户越多越好用）| 靠补贴/政府订单维持，撤了就塌 |
| 收入质量 | 真实商业化客户付费 | 关联方/政府补贴 > 30% |
| 客户黏性 | NDR > 100%（现有客户在扩大使用）| NDR < 80%（现有客户在收缩）|

**第二层：单位经济是否在改善**

好的期权型生意：毛利率斜率向上 + 现金消耗速度可控 + 收入增速 > 40%
糟糕的期权：毛利率为负（规模化解决不了）+ 现金快速消耗 + 增速减速

---

## 二、真假网络效应的判断（最重要，G4 核心遗产）

> 护城河是真是假，关键在这里。

**真网络效应**：用户越多，产品对每个存量用户越有价值。
- 例子：大模型 API（训练数据越多越准）、代码助手（更多代码库更懂语境）、协作平台（更多用户=更多协作场景）

**假网络效应**：靠规模+补贴维持，撤了用户就走。
- 例子：某些 AI 工具靠免费套餐圈用户，付费转化率接近 0
- 检验方法：**留存曲线**——用户增加是否让存量用户体验变好？次日/30日/12月留存率是否走平？

**实务判断**：
- AI 软件公司大多声称有网络效应，但真正有护城河的很少
- 数据护城河（私有数据训练）比算法护城河更持久（算法可以被追平，私有数据不能）
- 客户数据飞轮：客户用得越多 → 数据越多 → 模型越准 → 客户越不想走（这是真护城河）

## 三、现金跑道是硬约束（G5 核心遗产）

> **AI 软件早期公司：现金跑道是第一优先指标，没有之一。**

```
现金跑道 < 12 个月 → 融资风险红线，结论必须包含警告
现金跑道 12-18 个月 → 需要密切关注，融资压力存在
现金跑道 > 24 个月 → 相对安全，可以关注业务进展
```

**计算口径**（指标字典 D5 `runway`）：
- (货币资金 + 交易性金融资产) / 月均净现金流出
- 月均净现金流出 = −min(OCF − Capex, 0) / 12（近四季）
- 如果 OCF > 0 → 输出 `self_funded`，此时 runway 已不是核心约束

**融资依赖的隐藏风险**：
- 持续融资会稀释现有股东（`share_change` 指标追踪）
- 每轮融资的估值变化反映投资人对商业模式的信心
- 大比例 SBC（股权激励）是隐形成本，不能只看 Non-GAAP 利润

## 四、收入质量是核心前提

**先问这个问题，再看任何增长数字**：

> 收入里有多少是真实商业化，有多少是政府补贴/关联方订单/战略性采购？

**A 股 AI 公司的高发问题**：
- 政府数字化采购占收入 30%+ → 依赖政策周期，非市场化商业模式
- 大客户是控股股东关联方 → 交易公允性存疑，关联方收缩即崩塌
- 收入确认加速（预收款比例高但交付进度存疑）

**判断方法**：
1. 年报附注查前五大客户：是否有关联方？占比多少？
2. 补贴收入：政府补贴占营业利润 > 30% → 扣非对照必看
3. 合同负债 vs 营收增速：合同负债快速增加但营收没跟上 → 确认时间存疑

---

## 五、GMV ≠ 收入（平台类 AI 公司注意）

对于做 AI 平台/市场的公司（类似 G4 平台逻辑）：
- GMV 是交易流水，收入 = GMV × take rate（抽成比例）
- 别把 GMV 增长当收入增长
- Take rate 是否在下滑？下滑说明议价能力弱，或者在用低价换份额

## 六、关键红旗

| 红旗 | 触发条件 | 含义 |
|------|---------|------|
| **收入质量劣化** | 关联方/政府补贴收入占比 > 30%，或占比上升趋势 | 不是真实商业化，增长数字不可信 |
| **客户流失** | NDR < 100%，或主要客户合同未续约/降量 | 产品没有解决客户问题，商业模式有缺陷 |
| **规模化失败** | 毛利率持续为负，规模扩大后没有改善 | 单位经济根本转不正，继续烧钱是在毁灭价值 |
| **现金红线** | 现金跑道 < 12 个月 + 融资渠道不畅 | 生存威胁，需要降低确定性权重 |
| **股本稀释过速** | 股本年增速 > 8%（SBC + 融资稀释）| 每股价值被持续摊薄，账面增长是虚增 |
| **留存曲线下行** | 次日/30日/12月留存率持续下降 | 产品没有真实用户价值，网络效应是伪命题 |

---

## 七、推理顺序

```
1. 收入质量检查（先做，否则后面都没意义）
   → 真实商业化收入比例，关联方/补贴占比

2. 真假网络效应判断
   → 留存曲线、NDR，护城河是否真实

3. 单位经济改善斜率
   → 毛利率斜率（绝对值不重要，方向很重要）
   → 获客成本趋势（如有披露）

4. 现金跑道
   → 距融资风险红线有多远

5. 稀释修正
   → SBC 占收入比，每股口径增长

6. 估值（必须用期权思维）
   → DCF（收入拐点假设）/ PS / EV/Revenue
   → 当前价格隐含的商业化假设是否合理
```

## 八、估值（期权框架，不能套用成熟公司逻辑）

**当期亏损公司的估值禁区**：
- 禁用：PE（亏损，`not_meaningful`）
- 禁用：ROE（净资产可能为负，`not_meaningful`）
- 禁用：ROIC（分母无意义）
- 禁用：FCF/净利润（净利为负）
- 禁用：股息率（无分红）

**应该用的方法**：

| 方法 | 使用场景 | 核心假设 |
|------|---------|---------|
| 收入拐点 DCF | 主模型，3-5 年后达到稳态 | 稳态毛利率/FCF margin 假设要明确，不能偷懒 |
| PS（`ps_ttm`） | 对标同类可比公司 | 可比公司必须处于相似发展阶段，跨阶段对比无效 |
| EV/Revenue | 同 PS，但剔除净现金影响 | AI 软件公司现金多，EV 比市值更合理 |
| 反推 DCF | 验证当前价格的合理性 | 反推的稳态假设是否离谱？ |

**估值特别提醒**：
- 任何 AI 软件公司的估值都包含大量「如果商业化成功」的假设，**必须显式说出这些假设**
- 不同情景下（乐观/中性/悲观）的收入增速和稳态利润率假设必须分开给
- 当前价格往往 price in 了乐观情景，需要反推中性情景的安全边际

---

## 九、指标优先级（配合指标字典 v1.0）

> `★` = 本行业最优先

**必算**：
- `★` 现金跑道（`runway`，D5）——生存能力第一指标
- `★` 毛利率斜率（`gross_margin` 序列，赛道指标）——规模化是否兑现
- `★` 收入增速（`rev_yoy`, `rev_cagr_3y`）——必须 > 40% 连续 2 年才入「成长通道」
- PS（`ps_ttm`）/ EV/Revenue（`ev_revenue`）——估值锚
- 股本变化（`share_change`）——稀释监控

**结合情况算**：
- NDR 净收入留存率（赛道指标，SaaS 类必算）
- 研发费用率（`exp_ratio` 研发口径）
- SBC 占收入比（赛道指标，Non-GAAP 调整）
- 付费客户数 / ARR 增速（赛道指标，年报或公告披露）

**本行业禁用**：
- PE / ROE / ROIC / FCF yield（当期亏损，全部 not_meaningful）
- 用 Non-GAAP 利润做估值而不说明 SBC 加回方式

---

## 十、输出契约

- 结论前必须说明「收入质量」（真实商业化占比），这是所有判断的前提
- 现金跑道必须单独呈现，不能埋在财务数字堆里
- 估值必须显式说出「稳态假设」（什么时候盈利、稳态利润率是多少）
- 禁止输出「基于 PE 的目标价」——必须用 PS 或 DCF
- 结尾：证伪条件（收入增速放缓阈值、现金红线、NDR 临界值）+ 跟踪指标
