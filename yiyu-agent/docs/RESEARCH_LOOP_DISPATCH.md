# 研究起点、动态计划与取数分流

预处理准备标的、初始事实、行业画像及历史判断。它将这些材料放进 `research_seed`，不再生成正式问题清单。Agent 循环复用原有 ResearchPlan 生成问题和优先级，看到新证据后通过原有 `plan.update` 新增问题、调整优先级或回写结果。新流程不再因为“某类工具已成功”自动完成问题。

初始计划仍由一次模型规划过程产生（失败可重试并走原有确定性兜底），并非多模型投票。改进在于后续循环有证据反馈和修改权；这不保证初始判断一定正确。

## 一轮研究如何工作

1. Agent 根据用户目标决定研究需求，字段目录仅用于表达已有结构化能力。
2. 提交 `market.get_bundle` 时，字段需求可附 `data_needs`：字段、关联问题 ID、重要性、已有可靠证据 ID。
3. 循环在本地复用 Fetch Planner 读取 Registry、Source Mapping、当前 Data Pack 和 Provider 状态，不增加模型调用。
4. 有结构化能力的字段调用 `market.get_bundle`；未注册、无来源或已知 Provider 不可用的字段直接形成白名单搜索任务。独立任务在现有执行批次内并行，计算仍等待需要的结构化数据。
5. 结构化源实际调用后才暴露的失败，交回 Agent，根据缺口重要性在后续轮决定搜索。
6. 数据、检索线索和正文沿用现有 observation、证据包与 trace；`data_needs` 记录字段、问题、状态及证据 ID。网页证据不伪装成 Registry 标准数值，也不直接写回财务字段。
7. Agent 核验后用 `plan.update` 回写问题。关联的核心需求只有搜索摘要时，系统拒绝标记已回答；答不了保留原因。

例如同时请求“股价”和目录外的“客户续约意愿”：股价进入结构化取数，续约意愿直接搜索，两者并行。无需先等结构化工具完整返回才能发现目录外需求。

## 搜索规则

| 需求 | 执行方式 |
| --- | --- |
| 用户明确要求 | 优先；缺失必须在回答中交代 |
| 会改变核心结论 | 优先搜索 |
| 已有可靠证据足够回答 | Agent 引用已有证据 ID，系统确认 ID 存在后减少补搜 |
| 背景补充 | 预算允许才搜索 |

默认每轮请求总共最多执行 6 次搜索，同一稳定缺口最多 2 次；背景搜索不能占用最后 2 次搜索额度。同时受原有时间、工具调用总预算约束。更换关键词仍沿用同一 `gap_id`；缺少关联信息的旧搜索共用一个有限额度。精确相同调用仍复用缓存。次数限制由代码执行，重要性与证据是否足以回答仍由 Agent 判断。

重要性不能因取数困难下降。关联核心或明确需求尚未取得证据时，循环拒绝通过降级来绕过缺口；应标记答不了并说明原因。预算不足时停止补搜，披露证据不足并收窄结论。

## 网页核验

搜索后自动打开一条结果正文；打不开最多再试另一条，且计入工具预算。空正文或错误字典按失败处理。正文取得只表示“已读、待核验”，不自动表示问题解决。

| 来源或情况 | Agent 应核验什么 |
| --- | --- |
| 新浪财经、同花顺新闻 | 正文中的日期、事件和信息出处 |
| 雪球帖子 | 原话与上下文，观点按观点使用 |
| 新闻引用关键财报数字 | 需要精确口径时进一步追溯原报告 |
| 无法打开 | 使用其他可访问来源，不声称读过正文 |

白名单检索在本地复核返回域名，无结果直接返回空集，不再暗中降级全网。自动打开首条不保证它最相关；关联性、时效和口径仍需 Agent 判断。当前网页工具没有新增 PDF 解析能力，不能把二进制报告当作已核验的财报正文。

- `tests/test_research_dispatch.py`：字段分流、真实并发、搜索上限、替代证据、正文失败换源、摘要不能销项。
- `tests/test_preloop_wiring.py`：预处理不生成计划、循环生成并复用计划更新。
- 环节评测：05_plan、09_facts、11_loop、06_metrics、13_safety。05_plan 的在线用例需要真实模型服务，离线通过不等于在线质量验收通过。
