# 被测对象地图（skills）

> 这个目录不写代码，是一份**「用户能感知到的 AI 能力」↔「背后代码模块」的对照表**。
> 产品/运营看这份表，就能知道：某个功能上线前，对应哪套评测、挂在哪道工序或哪摞考卷上。

---

## 以渔 2.0 对外呈现的核心能力

| 用户感知的能力 | 一句话描述 | 对应评测位置 |
|---|---|---|
| **听懂我在研究什么** | 把一句口语（"帮我看看茅台"）解析成明确的研究意图 | `stage/01_intent/` |
| **认出研究对象** | 区分这是公司 / 行业 / 基金 / 宏观，并锁定准确标的 | `stage/02_entity/` |
| **选对研究方法** | 判断该用哪种研究框架（价值 / 成长 / 赛道…） | `stage/03_classify/`（已并入循环前处理） |
| **定研究粗细** | 决定挖多深、覆盖哪些维度（公司级 vs 业务线级） | `stage/04_granularity/` |
| **列研究计划** | 生成分阶段、有优先级、带护栏的研究计划 | `stage/05_plan/` |
| **算关键指标** | 计算 ROE、估值、现金流等量化指标 | `stage/06_metrics/`（公式层：冻结函数）+ `stage/12_metric_skill/`（工具层：输出契约与溯源） |
| **形成认知** | 把碎片信息归纳成投资观点（待落地） | `stage/07_cognition/`（TODO） |
| **判断是否研究够** | 判断信息是否充分、要不要继续挖（待落地） | `stage/08_sufficiency/`（TODO） |
| **核实事实** | 把 AI 提取的事实与原始资料比对，防编造 | `stage/09_facts/` |
| **画像与适配** | 给研究对象画公司画像、选数据采集适配器 | `stage/10_profiler/` |
| **跑完整研究循环** | 多轮「思考→行动→核验→收敛」直到出报告 | `stage/11_loop/` |
| **交出高质量报告** | 结论清晰、有来源、有风险、不编数 | `e2e/datasets/quality/` + `e2e/scripts/run_quality.py` |
| **守住安全底线** | 不泄密、不越权、不绕过护栏 | `e2e/scripts/test_hard_rules.py` + `e2e/scripts/gate_bypass.py` |

---

## 怎么用这份表

- 当你要**新增一个用户能力**：先在 `skills/README.md` 这里补一行，再决定它归到 `stage/` 的哪道工序，或 `e2e/datasets/` 的哪摞考卷。
- 当你要**验收某个功能**：顺着表找到对应评测，跑一遍看绿/红。
- 标了「（TODO）」的工序目前还没评测护航，是已知风险点，发版时需人工兜底。
