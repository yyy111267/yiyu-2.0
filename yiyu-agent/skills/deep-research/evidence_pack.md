# 四视角 Evidence Pack —— 中间推理结构（组织分析的强制前置）

**作用**：写最终研报之前，先以统一 JSON 完成「四视角证据收集 → 冲突对照 → 综合收敛」。
本步是**强制中间产物**，禁止跳过直接写散文。JSON 是最终结论的推理骨架，必须可追溯、可审计。

**编排**：不创建四个独立 Agent。你在**一个推理循环内**依次扮演四个视角，各输出一条统一 JSON，
再对照冲突、综合收敛——保证结构一致、口径可比、不产生多 Agent 漂移。

---

## 一、四视角 Evidence Pack（每个视角输出统一 JSON）

四个视角固定，不得增删改名。每个视角对**同一标的**独立收集证据、给出判断与置信度：

| 视角 | 关注维度 | 核心问题 |
|---|---|---|
| **巴菲特** | 生意质量、护城河、资本配置 | 这门生意 10 年后还在吗？护城河在变宽还是变浅？ROIC 与资本配置（分红/回购/再投资）是否优秀？ |
| **芒格** | 多元思维、激励机制、反向思考 | 它怎么会死？激励是否扭曲（SBC/压货/关联交易）？有哪些被忽略的跨学科风险？反过来想，空方核心论点是什么？ |
| **格雷厄姆** | 资产、估值、安全边际 | 当前价格相对净资产/盈利是否足够便宜？下行保护在哪？估值有安全边际还是透支了未来？ |
| **费雪** | 成长质量、研发、管理层、长期空间 | 成长是否高质量、可持续？研发投入与转化、管理层能力与诚信、长期市场空间（TAM）是否支撑？ |

**每个视角输出（严格 JSON，不得自由散文）：**

```json
{
  "master": "巴菲特|芒格|格雷厄姆|费雪",
  "stance": "看多|中性|看空|不适用",
  "core_argument": "一句话核心论据",
  "evidence": [
    {"claim": "证据支持的判断", "source": "指标/数据源", "weight": "strong|medium|weak"}
  ],
  "key_metrics": ["该视角最关心的 3-5 个指标名"],
  "judgment": {
    "verdict": "好生意|一般|差|无法判断",
    "confidence": "high|medium|low",
    "reason": "2-3 句推理，引用 evidence 中的来源"
  },
  "questions_raised": ["对其它视角或对标的的质疑"]
}
```

**铁律：**
1. `evidence.source` 必须可溯源到工具返回值：base_pack 指标名 / market 数据 / calc.run_code 输出 / web 来源 URL / 明确的定性推理。**禁止心算或凭记忆报数**（与 base_pack 铁律一致）。
2. 数据不足的维度：`stance` 填"不适用"，`judgment.reason` 注明"数据不足"，**不得编造**。
3. G5 / C 级分支（命中 bus_router 规则时）：巴菲特/格雷厄姆的估值维度降级为"暂无估值锚"，
   改用现金可支撑月数 / 盈利拐点确定性 / 技术采纳曲线判断；C 级按第一性原理提问，不硬判。
4. `questions_raised` 必须至少 1 条——每个视角都要挑战另外三个视角一次（交叉质疑）。

## 二、冲突矩阵（基于四视角对照）

把四视角判断放进矩阵，显式列出分歧与一致项：

```json
{
  "conflicts": [
    {
      "issue": "分歧点（估值是否安全 / 护城河是否稳固 / 成长是否可持续 / 激励是否扭曲…）",
      "view_a": "支持方视角 + 依据",
      "view_b": "反对方视角 + 依据",
      "adjudication": "收敛判断：谁的证据更硬 / 还是未化解"
    }
  ],
  "consensus": ["四视角一致认可的点"]
}
```

**要求：**
- 至少列出 2 个实质性分歧；无分歧也要列出 `consensus` 一致项；
- **未化解的分歧必须写入第三步的 `falsification` / `unresolved`，不得静默忽略。**

---

## 三、综合判断 + 证伪条件

基于 Evidence Pack 与冲突矩阵收敛：

```json
{
  "synthesis": {
    "verdict": "买入|观望|回避|期权型观察",
    "confidence": "high|medium|low",
    "reasoning": "综合四视角后的统一判断（200-300 字，说明如何裁决冲突矩阵中的分歧）"
  },
  "falsification": [
    {
      "condition": "什么数据/事件出现会推翻本判断",
      "check_metric": "盯什么指标或数据源",
      "trigger": "触发阈值"
    }
  ],
  "unresolved": ["未化解的质疑"]
}
```

## 四、成文（推理骨架 → 研报散文）

以上 JSON 是推理骨架。最终研报按 `bus_router/{group}/skill.md` 的输出契约组织成散文：
生意本质 → 护城河 → 风险与红旗 → 管理层 → 估值 → 证伪条件与跟踪指标。

- 四视角立场**融合进各章节论证**，禁止以「巴菲特认为」「芒格指出」罗列前缀（保持研报连贯叙述）；
- 分歧的处理方式（谁被采纳、谁被反驳）要在对应章节体现；
- `falsification` 与 `unresolved` 必须落到研报结尾的"证伪条件与跟踪指标"章节。
