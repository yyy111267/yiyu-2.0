# 多业务公司 · SOTP 分析框架

## 你会收到什么

分类器给你的输入：
- `primary_group` — 主导商业模式（收入占比最高）
- `sotp_tier` — 数据可得性档位（1/2/3/4），**决定你能做多深**
- `is_conglomerate` — 是否触发多业务处理
- 整体口径的 core 指标 + 主组 base_pack
- 年报/财报原始文本 + 受控联网搜索结果（分部数据的两个合法来源）

你的任务：按下面的档位和视角，做分部拆解分析，最后给带证伪条件的结论。

### 数据来源规则（先读这个）

数据不限于财报文本。联网搜索走 **来源白名单**（已有配置，无需新建），判定顺序：

1. **先财报**：从年报附注/财报文本提取分部收入/利润/投入资本
2. **再搜索**：财报提取不全 → 调用 `web.search(sources=...)` 补
   - `sources="finance"` — 财经媒体+官方信披（雪球/新浪/东财/巨潮/交易所，默认首选）
   - `sources="official"` — 仅官方信披（巨潮/上交所/深交所/港交所/SEC），查分部披露优先用这个
   - `sources="company"` — 公司官网放行
   - 查询词加"公司名+业务线+分部收入/利润"，避免无关结果
3. **才算缺**：财报+白名单搜索都没有 → 才标 NOT_AVAILABLE / 降级

**白名单校验标记（看返回结果）**：
- `sources_verified=true` → 结果经过白名单域名校验，可直接引用
- `sources_verified=false` → 白名单无结果、降级全网搜索，须在来源里标注"未经白名单校验"
- 白名单文件在 `toolkit/web/data/finance_sources.json`，如需要新源在此增删

**每条进入估值或结论的数字都必须带来源标注**：财报数字标 `财报XX年附注P.xx`，
搜索数字标 `web检索：[URL]`。无来源的数字一律不采用。

## 第一原则：业务拆分是分析动作，不是分类器的输出

分类器**不会**给你现成的业务线清单。你要像分析师一样，在分析中主动拆业务线——
**一次检索打包多业务线**（如 `游戏 广告 金融科技 云 AI投入 分部收入 分部利润`），
先从年报附注/财报文本里提取各业务线的收入和利润，提取不全再用
`web.search(sources=finance/official)` 白名单搜索补（用"公司名+业务线+分部收入/利润"
限定，避免搜到无关数据），而不是逐条业务单独跑一遍。

### 三个固定视角（保证可复现，不即兴发挥）

同一家公司在不同分析目的下，业务分类逻辑不同。**必须用且只用这三个视角**，
不要每次即兴创造新分法（那会导致结论不可复现）：

| 视角 | 用途 | 腾讯示例 |
|---|---|---|
| **取数视角** | 覆盖所有业务线取收入/利润 | 游戏 / 广告 / 金融科技及企业服务 / 云 / AI投入 |
| **护城河视角** | 按壁垒类型分析竞争力 | 社交网络效应 / 内容生态 / 商业化工具层 / AI赋能层 |
| **增长视角** | 按增长引擎分析驱动 | 游戏 / 广告 / 金融科技（云并入此）/ AI（增量变量） |

三个视角的拆法不同是正常的、正确的（游戏在取数视角是独立线，在护城河视角归入内容生态）。
但**视角的种类固定为这三个**，不允许多也不允许少。

## 第二原则：按 sotp_tier 决定分析深度（可得性驱动降级）

### Tier 1 — 完整 SOTP（分部收入+利润+投入资本齐全）

1. 每个分部：加载对应 group 的 `step7_valuation`，取分部收入/利润/投入资本
2. 算**分部 ROIC**（识别哪块创造价值、哪块毁灭价值）
3. 每个分部用自己的估值模型算价值
4. 加总 − 净债 + 集团现金 − 集团折价 = 内在价值
5. 投资资产按公允价值/持仓市值单列

### Tier 2 — 分部估值 + 整体质量（最常见，腾讯落这里）

分部收入/利润有，但分部投入资本**经财报+受控搜索后仍拿不到**。这一档要做三件事：

1. **估值层（做分部）**：各分部用自己商业模式的估值模型
   - 游戏/广告（G4）→ PS 或 DCF
   - 金融科技（G4，支付平台）→ PS
   - 云（G5，投入期）→ EV/Revenue
   - 投资资产 → 直接用持仓市值（公允价值）
   - 加总各分部价值 − 净债 − **集团折价**（判定见下方公式，不是拍脑袋）

2. **质量层（用整体）**：ROIC/现金流/毛利率用**合并口径**，
   但**必须显式标注"合并口径，分部投入资本财报与搜索均不可得，无法拆解分部ROIC"**。
   ⚠️ 绝不伪造分部 ROIC。若搜索找到了第三方测算的分部投入资本，可引用但必须标注
   来源与测算假设；合并 ROIC 对混合公司信息量低，要说明这个局限。

3. **定性层（借鉴问财，按业务线定性）**：
   用取数视角逐业务线定性分析增长与边际变化，**明确指出哪块业务在投入期
   拖累整体回报**（如"AI 投入与云业务处于投入期，压低了合并 ROIC，
   但游戏/广告分部的真实回报显著高于 15.86% 的合并值"）。

### Tier 3 — 主业定性 + 整体估值（带 caveat）

分部数据经财报+受控搜索后仍拿不到，或辅业太小可忽略。退回主组 skill 逻辑，
但结论必须声明："辅业数据不可得（财报与搜索均无），本估值主要基于主业，辅业价值可能被低估/高估"。

### Tier 4 — 未上市多业务（替代数据推断）

适用：`is_listed=false` 且 `is_conglomerate=true`（字节跳动等未上市多业务公司）。

1. 用替代数据粗估各业务线规模：招聘规模、融资估值、应用排名、专利、媒体报道
2. SOTP 用粗估占比做**定性加总**，不做精确估值
3. 每一条分部数据都标注来源和置信度（高/中/低）
4. 结论大字标注"未上市，分部数据为推断，置信度低"
5. **禁止输出低估/高估结论**，只允许"方向性判断 + 证据缺口"（与 C 级处理衔接）

## 集团折价判定（不是固定范围，按因素判断）

> 混合企业市场通常给折价，但 15% 和 25% 差别很大，不能随机选一个。

按以下因素逐条判断，**每条都要给结论，最终给一个确定百分比并说明理由**：

| 因素 | 折价偏大（+） | 折价偏小（−） |
|---|---|---|
| 业务相关性 | 各分部业务互不相关（游戏+云） | 业务协同强（支付+云共用基础设施） |
| 分部披露质量 | 只披露合并数、不拆分部 | 分部披露清晰、可验证 |
| 控股层级 | 多级控股、中间层多 | 单层上市主体 |
| 市场偏好 | 市场偏好"纯业务"公司（折价大） | 市场认可混合平台（如腾讯生态溢价） |
| 历史折价 | 同类混合公司历史折价高 | 同类公司历史折价低甚至溢价 |

**基准 20%，按上述因素 ±5%，最终必须写"我选了 X%，因为…"**。

## stage 判定（分部级，不是公司级）

多业务公司的分部可能处于不同生命周期：
- 游戏 = 成熟（profitable）
- 云 = 成长（growth）
- AI 投入 = 早期（early）

**必须遵守**：
1. 公司整体 stage 由主业务 stage 决定（用于整体估值锚）
2. **每个分部独立判定 stage**（连续4季分部净利 → profitable；分部亏损但高增速 → early/growth）
3. 输出时必须列各分部 stage 表，不能用整体 stage 代替

## 分部估值时各组用什么模型（速查）

| 分部商业模式 | 估值模型 | 禁用 |
|---|---|---|
| G1a 品牌消费 | DCF + 正常化PE | — |
| G1b 公用 | DDM 股息贴现 | FCF估值 |
| G2 金融 | PB-ROE / P-EV | 单纯PE |
| G3 周期 | 全周期PB | 单年外推 |
| G4 平台 | PS / DCF / 单位经济 | 单纯PE |
| G6 硬件 | PE周期调整 / EV-EBITDA | — |
| G5 未盈利分部 | EV/Revenue | PE/ROE/FCF |
| 投资资产 | 公允价值/持仓市值 | 建模（直接用市值） |

## 常见误判（务必规避）

1. **用整体一个 PE 估混合公司。** 腾讯不能用一个 PE，游戏和云的估值逻辑天差地别，必须分部。
2. **把合并 ROIC 当成公司真实回报。** 高回报游戏 + 负回报 AI 投入被平均掉，合并值误导性极强。
3. **伪造分部 ROIC。** 投入资本先找财报、再用白名单搜索补，仍拿不到就标 NOT_AVAILABLE，
   不要硬拆一个假的。第三方测算可引用但必须标来源和假设。
4. **漏掉投资资产。** 腾讯持有的美团/拼多多等股权是巨额价值，必须单列进 SOTP。
5. **漏掉集团折价。** 混合企业市场通常给折价，不加会高估；但折价要按因素判定，不拍脑袋。
6. **每次业务拆法不一致。** 严格用三个固定视角，不即兴创造新分法。
7. **未上市多业务走普通单组流程。** Tier 4 必须用替代数据做定性 SOTP，不能退回普通估值。
8. **用整体 stage 代替分部 stage。** 分部生命周期不同，估值锚必须分部级。
9. **搜索不走白名单 / 引用未校验结果。** 一律用 `web.search(sources=finance/official)`；
   `sources_verified=false` 的结果必须标注"未经白名单校验"，不得当作白名单可信数据。

## 输出结构（严格遵守）

- **判断**：低估 / 合理 / 高估 / 数据不足（注明 sotp_tier；Tier4 禁止前三个，只允许"方向性判断+证据缺口"）
- **分部价值表**：每个分部的估值方法 + 分部价值 + 占比
- **分部 stage 表**：每个分部独立判定生命周期（Tier1/2 必填，Tier3/4 标注推断）
- **SOTP 汇总**：各分部加总 − 净债 − 集团折价（写明选了百分之几及理由） = 内在价值 vs 当前市值
- **价值创造/毁灭判断**：哪块业务在创造价值、哪块在拖累（Tier1有分部ROIC则量化，Tier2定性）
- **数据来源表**（必填）：分部价值表里每个数字旁边标注来源
  （`财报XX年附注P.xx` / `web检索：[URL]`），无来源数字不允许出现
- **数据局限声明**（必填）：哪些是合并口径、哪些分部数据"财报+搜索后"仍不可得、
  Tier4 每条分部数据的置信度、搜索数据与财报口径冲突时的取舍说明
- **关键假设** + **证伪条件**（必填）+ **跟踪指标**

---

## 禁止事项

- 不得引用指标表/提取数据中不存在的数字（治理层逐个核对）
- **不得使用无来源标注的数字**：每个进入估值/结论的数字必须有来源
  （财报页码 或 web 检索 URL），这是数据可信的唯一凭据
- 不得伪造分部 ROIC / 分部投入资本
- 不得用单一估值模型估多业务公司
- 不得把各分部或各维度打分加权成一个总分
- Tier2/Tier3 必须显式声明数据局限，不得假装做了完整分部分析
- Tier4 不得输出精确估值数字，只给方向性判断
