# 以渔 2.0 环节评测用例集：公司研究循环前处理

## 一、评测范围与对象

本用例集覆盖 PRD 5.3 公司研究循环前处理的四个环节及其传导约定：环节① 事实包构建、环节② 研究粒度决策、环节③ 公司画像与 Adapter 路由、环节④ 研究计划生成。被测边界如下：

| 模块 | 起点 | 终点 | 不在本集范围 |
| --- | --- | --- | --- |
| 事实包构建 | current_entity（5.2 实体解析产物） | company_facts（带 facts_version） | 研究循环中的增量取证、指标计算正确性 |
| 研究粒度决策 | company_facts | granularity_decision（mode + units[]） | — |
| 画像与 Adapter 路由 | company_facts + units[] | 每单元 company_profile + selected_adapter | Adapter 问题集内容质量（资产章验收） |
| 研究计划生成 | 四件套上游输入 | research_plan（P0/P1/P2 问题清单） | 计划执行质量、报告质量（端到端评测） |
| 跨环节传导 | 前处理启动 | 四件套写入任务 Context | SOTP 估值计算本身（估值维度评测） |

评测哲学沿用 PRD 第 8 章的断言式口径：先把"什么算好"定义成可判定的断言，再构造输入去触发它。正向用例验证前处理能做到什么，防御用例验证它不该做什么；防御用例按 pass^k 口径执行（连续 k 次全过才算过，k=5），因为污染下游的错误不允许偶发。

本用例集与第 8 章的关系：第 8 章"环节级门禁"已列出前处理各环节的门禁指标（source_trace 覆盖率 ≥ 98%、粒度决策一致率 ≥ 95%、选型一致率 ≥ 95%、计划一次通过率 ≥ 90% 等），本用例集是这些门禁的落地用例与开发验收依据；与 36 条核心回归集（端到端为主）互补，不重复计入。

## 二、先定义什么算好

### 2.1 事实包构建的四条质量标准

1. **抽得准。** one_line_business、segments、financial_snapshot 等结论性字段必须来自信源事实，source_trace 逐字段留痕；无溯源即非法，模型记忆直出视同编造。
2. **评得稳。** info_richness 评级依据明确（财报年限与审计连续性、卖方覆盖、主业可拆分度等），同一 facts_version 重复评级一致；C 级收窄研究范围、显式列出无法回答的问题，禁止以行业均值或想象补值。
3. **缓得住。** 事实包与 facts_version 绑定缓存，同一任务内环节②③④与研究循环共享，不重复检索；仅版本变更（新财报等）才重建。
4. **降得下。** 检索/抽取失败重试一次，仍失败降级为仅结构化数据源，缺口显式记入 open_questions，不阻断流程也不静默继续。

### 2.2 研究粒度决策的四条质量标准

1. **默认整体。** 产品、地区、渠道等分类仅作经营分析维度，披露多个分类不构成拆分理由。
2. **拆必有据。** split 须同时满足「至少一项显著差异（盈利模式/护城河来源/资本投入/估值逻辑）+ 不单独研究会显著影响判断」；每个 unit 的 reason 必须显式命中差异条件并给事实依据，不接受空泛理由。
3. **判得一致。** 粒度决策与 facts_version 绑定缓存，同一版本重复判断结论一致；不出现同一任务内「一会儿整体、一会儿拆分」。
4. **兜得住。** 校验不通过重试一次，仍不通过回退 mode=whole（整体作为单一 unit）；下游 per-unit 路由始终有合法输入。

### 2.3 画像与 Adapter 路由的四条质量标准

1. **标签带证。** 5 个维度标签（发展阶段/收费方式/资本强度/周期属性/价值链位置）各带 value/evidence/confidence 三元组；置信度低于 0.6 的维度列入 unverified_tags 待补证，低置信标签不驱动强结论。
2. **选型合法。** selected_adapter 必须是目录内合法 ID，幻觉 ID 一律拦截；标签取值在枚举范围内，越界即回退通用 Adapter 并标记 pending_verify、在产物中外显。
3. **per-unit 独立。** split 下每个研究单元独立画像与选型；价值投资 Core Skill 对所有单元固定生效，Adapter 只叠加研究偏好不替换母框架。
4. **预算受控。** 任务级 Skill 注入按 token 预算（初值 8k）控制总量，超预算低权重分部降级为目录摘要注入，不驳回重选、循环需要时再升级全文。

### 2.4 研究计划生成的四条质量标准

1. **七维不漏。** 母框架 7 个维度（生意本质/生意质量/护城河/增长与再投资/管理层与资本配置/逆向风险/估值与安全边际）均有处理决定：设独立问题、由其他问题合并覆盖（标注所覆盖维度）、或显式豁免并附一句话理由；豁免项在产物中外显。
2. **只列问题。** 计划是「待回答的问题 + 完成标准 + 证据需求」，不包含任何投资判断；结论由研究循环的证据驱动生成。
3. **认知复用。** 用户既有认知转成起始问题、验证型问题或显式对比验证问题；冲突认知不静默沿用或覆盖。
4. **落得下。** 每题必填字段齐全、priority/dimension 枚举合法、level/unit_id 引用合法；校验失败重试上限 2 次后 fallback Core Skill + Adapter 推荐清单作为默认计划，并外显标注。

### 2.5 跨环节传导的三条质量标准

1. **单一计划。** split 不复制 N 份计划，一份计划混装公司级与分部级问题，靠 level + unit_id 标记归属，P0 跨单元统一排序。
2. **全链复用。** facts_version 未变更时，环节②③命中缓存不重复调用模型；前处理成本随任务摊薄。
3. **状态持久。** 四件套全部为结构化 JSON 写入任务 Context，随任务状态持久化（跨轮、跨会话保留）。

## 三、评判框架

### 3.1 P0 与 P1 的划分原则

**P0（致命项）：** 触发即 FAIL，不做累计。判定原则是「错误会污染下游全链路或突破安全边界」：

事实包构建：

* 结论性字段编造：one_line_business、segments 收入占比、financial_snapshot 关键数字无信源支撑（模型记忆直出）
* source_trace 缺失的抽取结果未被打回（溯源护栏失效）
* 检索失败后未降级、未记 open_questions，静默继续（对应第 8 章「工具失败未解释未降级」P0 项）
* C 级信息稀缺标的以行业均值或想象补值
* 使用白名单外信源

研究粒度决策：

* 方向错误：该拆不拆（重大分部差异被整体叙事吞掉）、不该拆乱拆（以用例预置答案为准），下游研究骨架随之错误
* split 模式下仅 1 个研究单元的逻辑矛盾未被拦截
* 空泛拆分理由（未命中四项差异条件）被放行进入 units
* 置信度低于 0.6 未补证据、未回退，直接采用
* facts_version 变更后仍复用旧粒度决策（版本绑定失效，下游研究过期数据）

画像与 Adapter 路由：

* 幻觉 Adapter ID 未被拦截，进入下游（研究方法错配）
* 枚举越界标签未回退直接使用
* 回退通用 Adapter 后未标记 pending_verify、未在产物外显（用户与评测无从追溯）

研究计划生成：

* 母框架 7 维存在无处理决定的维度（覆盖校验失败仍放行）
* unit_id 引用非法未被拦截
* 计划夹带投资判断或结论
* 用户冲突认知被静默沿用或覆盖，未生成显式对比验证问题（第 8 章 P0 项）
* 校验失败后未按规格 fallback（无限重试或直接崩溃）

**P1（扣分项）：** 每命中一条扣 1 分，累计计算。判定原则是「方向正确但违反行为规格或效率标准」：

* 结构性字段缺失或标注错误：info_richness 评级错误、confidence 缺失、scope 描述不清、selection_reason 缺失
* 冗余调用：facts_version 未变却重新检索、重新粒度判断、重新画像路由（缓存护栏失效的轻量表现）
* 降级产物未标注：回退 whole / 回退通用 Adapter 后未在产物中外显说明
* open_questions 未记录数据缺口
* 豁免维度未附一句话理由
* 主选 + 备选 Adapter 配置缺失（引导值未生效）
* token 预算超限未降级注入
* units 超 4 参考上限未触发遥测告警；P0 问题数超参考上限未告警
* 计划问题缺少证据需求或完成条件（字段不完整但未触发校验打回的边缘情况）

### 3.2 单条用例判定

| 判定 | 条件 |
| --- | --- |
| PASS | 未触发任何 P0，P1 扣分为 0 |
| PARTIAL | 未触发任何 P0，P1 扣分 1-2 分 |
| FAIL | 触发任一 P0，或无 P0 但 P1 扣分 ≥ 3 分 |

### 3.3 套件级判定与发布门槛

* 防御用例：全部必须 PASS，且按 pass^k = 100% 执行（每条连跑 5 次全过）；任何一次 FAIL 即阻塞发布。
* 正向用例：PASS + PARTIAL 合计占比 ≥ 90%，且 P0 零出现。
* 量化指标：2.6 节及格线全部达标方可放行；未达标项阻塞对应环节验收（事实包验收看 C 类指标，粒度决策看 D 类，路由看 E 类，计划看 F 类）。
* 线上观测补充：前处理总耗时与成本（P95）、缓存复用率、计划改写幅度，及格线初值待线上标定后回填。

## 四、事实包构建用例（C 类）

### 4.1 用例索引（正向）

| 编号 | 场景 | 验证点 |
| --- | --- | --- |
| C-01 | 单一主业公司事实包 | 结构完整 + 逐字段溯源 |
| C-02 | 多业务分部结构抽取 | segments 收入构成 + 占比口径合理 |
| C-03 | A 级信息充分评级 | 评级正确 + 反共识检查传导标记 |
| C-04 | C 级信息稀缺评级 | 收窄范围 + 显式列缺口 + 不补值 |
| C-05 | 缓存复用 | facts_version 命中，跳过检索 |
| C-06 | 信源不足升级检索 | 触发年报及公告检索补足 |

### C-01 单一主业公司事实包完整构建

* **初始状态**：任务状态含 current_entity = 兆易创新（603986.SH）；白名单检索回放夹具已冻结（信源快照含年报与交易所披露）。
* **输入**：user_goal「研究一下兆易创新」。
* **期望行为**：联网检索 + 结构化抽取产出完整 company_facts，写入缓存并绑定 facts_version。
* **成功条件**：
  * P0｜one_line_business 来自信源事实，source_trace 指向具体信源与时点。
  * P0｜financial_snapshot 关键数字（收入、毛利率、经营现金流、资本开支）带时点且 trace 可证。
  * P1｜segments、info_richness、open_questions、facts_version 字段齐全。
  * P1｜info_richness 评级依据可从 source_trace 复核（财报年限、卖方覆盖等）。

### C-02 多业务分部结构抽取

* **初始状态**：current_entity = 腾讯控股（0700.HK）；冻结夹具含年报分部披露。
* **输入**：user_goal「研究一下腾讯」。
* **期望行为**：segments[] 抽出增值服务、网络广告、金融科技与企业服务等分部，每分部含名称、收入占比、客户、收费方式。
* **成功条件**：
  * P0｜各分部收入占比来自信源，合计口径合理（接近 100% 或差额可解释为「其他」）。
  * P1｜每分部的客户与收费方式字段非空且与信源一致。
  * P1｜source_trace 覆盖每个分部字段。

### C-03 A 级信息充分评级与反共识传导

* **初始状态**：current_entity = 贵州茅台（600519.SH）；冻结夹具信息充分（多年审计财报、充分卖方覆盖）。
* **期望行为**：info_richness 评级为 A；评级传导标记存在，下游按 A 级口径额外触发反共识/证伪检查。
* **成功条件**：
  * P0｜info_richness = A，且产物携带反共识检查传导标记（防共识过强导致人云亦云）。
  * P1｜评级依据（财报年限与审计连续性、卖方覆盖等）可追溯。
  * P1｜评级随事实包缓存，下游表达强度档位可识别。

### C-04 C 级信息稀缺收窄不补值

* **初始状态**：current_entity 为披露有限的新上市公司；冻结夹具仅返回有限信息（无分部附注、卖方覆盖稀少）。
* **期望行为**：info_richness = C；缩小研究范围、显式列出无法回答的问题；缺失字段保持缺失。
* **成功条件**：
  * P0｜info_richness = C。
  * P0｜未以行业均值或想象补值（缺失字段保持缺失或标注不可得）。
  * P1｜研究范围收窄 + open_questions 显式列出无法回答的问题。
  * P1｜结论性字段的表达强度按 C 级档位调整。

### C-05 缓存复用跳过检索

* **初始状态**：同一任务此前已构建 facts_version = v1 的 company_facts，缓存有效。
* **输入**：同任务再次触发事实包构建（如二次研究请求、升级完整研究）。
* **期望行为**：直接命中缓存返回 v1，不重新检索。
* **成功条件**：
  * P0｜返回 v1 缓存产物，关键字段与首次一致（无漂移）。
  * P1｜trace 中无新的联网检索调用。

### C-06 信源不足升级年报检索

* **初始状态**：基础白名单检索夹具只含概览信息，不含分部附注细节；年报及公告检索工具可用。
* **期望行为**：判断依赖分部附注时，调用年报及公告检索工具补足。
* **成功条件**：
  * P0｜最终 company_facts 的分部细节来自年报检索结果且 trace 可证。
  * P1｜升级检索有明确触发条件（信息不足/冲突/依赖附注），非默认全量调用。

### C-D1 溯源缺失打回

* **初始状态**：白盒环境，抽取环节 mock 返回部分字段缺失 source_trace 的结果。
* **期望行为**：溯源必填护栏生效，非法结果打回补溯源。
* **成功条件**：
  * P0｜缺 source_trace 的字段未进入 company_facts 交付（判非法）。
  * P1｜打回后补溯源再通过，trace 记录打回事件。

### C-D2 检索失败降级不阻断

* **初始状态**：白盒环境，联网检索 mock 全部失败（超时/报错）；结构化数据源可用。
* **期望行为**：重试一次仍失败，降级为仅结构化数据源，缺口记入 open_questions。
* **成功条件**：
  * P0｜降级为仅结构化数据源后流程未阻断，产出可用事实包。
  * P0｜数据缺口显式记入 open_questions，未静默继续。
  * P1｜重试策略执行（非一次失败即放弃）。
  * P1｜产物中标注降级状态（下游按缺口口径调整判断强度）。

### C-D3 信源冲突不臆断

* **初始状态**：白盒环境，两个白名单信源对同一指标口径冲突（如毛利率年报口径与 TTM 口径数值不一致）。
* **期望行为**：不无依据地静默选定某一口径；冲突显式记录。
* **成功条件**：
  * P0｜未在无依据情况下静默选定某一口径并抹掉冲突。
  * P1｜冲突记入 open_questions（或字段级备注），两口径均可追溯。

### C-D4 零信源不凭记忆生成

* **初始状态**：白盒环境，检索回放对某字段返回空（信源无该信息）。
* **期望行为**：缺失字段保持缺失，不凭模型记忆填充。
* **成功条件**：
  * P0｜缺失字段未凭模型记忆填充（如编造毛利率数字或主营业务描述）。
  * P1｜缺口记入 open_questions。
  * P1｜info_richness 按实际信息量下调评级。

### C-D5 白名单外信源拦截

* **初始状态**：白盒环境，检索夹具中混入白名单外来源的结果。
* **期望行为**：信源分级拦截生效，白名单外来源不进入 source_trace。
* **成功条件**：
  * P0｜白名单外信源未进入 source_trace（未作为任何字段的依据）。
  * P1｜若使用 B 级讨论类信源，产物中注明非官方口径。

## 五、研究粒度决策用例（D 类）

### 5.1 用例索引（正向）

| 编号 | 场景 | 验证点 |

| D-02 | 茅台类分类不拆 | whole + 分类仅作分析维度 |
| D-03 | 伊利类同构不拆 | whole + 业务多但盈利模式同构 |
| D-04 | 决策复用 | facts_version 未变不重判 |
| D-05 | 版本变更重判 | 新财报改变分部口径触发重判 |

### D-01 显著分部差异正确拆分

* **初始状态**：company_facts（腾讯，facts_version = v1，含游戏/广告/金融科技分部）已就绪。
* **期望行为**：mode = split，产出游戏、广告、金融科技三个研究单元，每单元 reason 显式命中差异条件。
* **成功条件**：
  * P0｜mode = split，units 划分与预置答案一致（游戏/广告/金融科技或同粒度合理划分）。
  * P0｜每单元 reason 明确关联「盈利模式/护城河来源/资本投入/估值逻辑」至少一项并给事实依据。
  * P1｜confidence、facts_version、open_questions 字段齐全。
  * P1｜units 数量 ≤ 4 参考上限（3 单元合规，未触发告警）。

### D-02 披露多分类默认整体

* **初始状态**：company_facts（贵州茅台，含茅台酒/系列酒产品线与直销/批发渠道分类）已就绪。
* **期望行为**：mode = whole，分类仅作经营分析维度，不构成研究单元。
* **成功条件**：
  * P0｜mode = whole，未把产品线或渠道拆成研究单元。
  * P1｜units 为公司整体单一单元，reason 说明整体判断依据。

### D-03 业务同构不拆分

* **初始状态**：company_facts（伊利股份，含液态奶/奶粉/冷饮分部）已就绪。
* **期望行为**：业务虽多但共享品牌、渠道、客户群，盈利模式同构，mode = whole。
* **成功条件**：
  * P0｜mode = whole（反例规格：拆开导致护城河判断失真）。
  * P1｜决策理由体现同构性判断依据（品牌/渠道/客户群共享）。

### D-04 决策复用不重判

* **初始状态**：同任务此前已产出 granularity_decision（mode = whole，facts_version = v1）缓存有效。
* **输入**：同任务再次触发粒度决策（facts_version 未变）。
* **期望行为**：直接复用上次判断，不调用模型。
* **成功条件**：
  * P0｜复用缓存结论，与上次一致。
  * P1｜trace 中无粒度判断模型调用。

### D-05 版本变更触发重判

* **初始状态**：缓存中存在 v1 决策；新财报发布改变分部口径，事实包重建为 v2（facts_version 变更）。
* **期望行为**：基于 v2 重新触发粒度判断。
* **成功条件**：
  * P0｜基于 v2 重新判断，未沿用 v1 旧结论（版本绑定失效即 P0）。
  * P1｜新决策绑定 facts_version = v2。

### D-D1 过度拆分被护栏拦截

* **初始状态**：白盒环境，粒度判断 mock 输出按产品线拆分（如把茅台拆成「茅台酒单元/系列酒单元/渠道单元」），reason 为「产品线差异明显」（未命中四项差异条件）。
* **期望行为**：护栏校验识别 reason 未命中差异条件，打回重判。
* **成功条件**：
  * P0｜过度拆分结果未直接放行（打回或纠正为 whole）。
  * P1｜打回重试后收敛 whole 或合法 split。
  * P1｜trace 记录打回原因（reason 未关联差异条件）。

### D-D2 空泛拆分理由被打回

* **初始状态**：白盒环境，粒度判断 mock 输出 split + reason =「业务较多，比较复杂」。
* **期望行为**：空泛理由判非法，打回重判。
* **成功条件**：
  * P0｜空泛理由未进入 units 交付（打回生效）。
  * P1｜重试后 reason 达标（显式命中差异条件）或回退 whole。

### D-D3 置信度不足补证据后回退

* **初始状态**：白盒环境，粒度判断 mock 输出 confidence = 0.45 的 split 判断。
* **期望行为**：低置信不直接采用，先补证据重判；仍不足则回退 mode = whole。
* **成功条件**：
  * P0｜低置信输出未被直接采用。
  * P0｜回退后 mode = whole（整体单一 unit），下游 per-unit 路由有合法输入。
  * P1｜补证据重判流程执行（先重判再回退，非直接跳过）。

### D-D4 split 单单元矛盾判非法

* **初始状态**：白盒环境，粒度判断 mock 输出 mode = split 且 units 仅 1 个。
* **期望行为**：逻辑矛盾判定非法，打回重判。
* **成功条件**：
  * P0｜矛盾输出被拦截，未进入下游。
  * P1｜重判后收敛 whole 或合法多单元 split。

### D-D5 同版本重复判断一致

* **初始状态**：同一 company_facts（facts_version = v1），绕过缓存的直判模式。
* **执行**：重复触发粒度判断 5 次。
* **成功条件**：
  * P0｜pass^5：5 次结论一致（mode 与 units 划分均不变），任一次漂移即 FAIL。
  * P1｜若出现漂移，置信度差异可从 trace 归因。

说明：门禁统计口径为一致率 ≥ 95%（大样本回归），单条用例按 pass^5 保守执行；两者不一致时以更严者为准。

## 七、研究计划生成用例（F 类）

### 7.1 用例索引（正向）

| 编号 | 场景 | 验证点 |
| --- | --- | --- |
| F-01 | whole 基础计划 | 7 维覆盖 + 每题字段完整 |
| F-02 | 用户认知复用 | 命中/验证/冲突三种参与方式 |
| F-03 | split 计划混装 | level + unit_id 标记 + P0 跨单元排序 |
| F-04 | 显式豁免 | 豁免维度附理由 + 产物外显 |
| F-05 | Adapter 偏好注入 | per-unit 偏好问题进入计划 |

### F-01 基础计划七维覆盖完整

* **初始状态**：四件套上游输入齐备（facts + whole 粒度 + 画像 + Adapter）；用户认知库为空。
* **期望行为**：一次生成 research_plan，7 维均设独立问题，每题字段完整。
* **成功条件**：
  * P0｜母框架 7 维（生意本质/生意质量/护城河/增长与再投资/管理层与资本配置/逆向风险/估值与安全边际）均有处理决定。
  * P0｜每题 priority 枚举合法（P0/P1/P2）、dimension 枚举合法。
  * P1｜每题含决策相关性、证据需求、完成条件。
  * P1｜计划不含任何投资结论。

### F-02 用户认知三种参与方式

* **初始状态**：用户认知库预置三类条目：① 与护城河问题直接相关的认知（如「茅台品牌力是核心护城河」）；② 可证伪规则（如「高研发公司不能只看利润表」）；③ 与本次判断可能冲突的认知（如「白酒行业已见顶」）。
* **期望行为**：三类认知分别转为起始问题标记、验证型问题、显式对比验证问题。
* **成功条件**：
  * P0｜① 类认知对应问题标记「已有用户认知起点」（循环优先验证而非重新论证）。
  * P0｜② 类转成验证型问题列入计划。
  * P0｜③ 类生成显式对比验证问题，未静默沿用或覆盖。
  * P1｜认知参与方式在计划标注或 trace 中可追溯。

### F-03 split 计划混装与跨单元排序

* **初始状态**：腾讯 split 三单元（游戏/广告/金融科技）四件套就绪。
* **期望行为**：一份计划混装公司级与分部级问题，P0 跨单元统一排序。
* **成功条件**：
  * P0｜计划为 1 份（非 3 份），level = company 与 level = segment 混装。
  * P0｜segment 问题的 unit_id 均存在于 granularity_decision.units[]；公司级问题 level = company 不归属单元。
  * P1｜P0 问题跨单元统一排序（重要性 × 信息缺口 × 依赖顺序），非「先跑完游戏再跑广告」。
  * P1｜公司级共享证据类问题（如合并现金流）只列一次。

### F-04 不适用维度显式豁免

* **初始状态**：未上市标的或估值数据确实不可得的场景（估值维度不适用）。
* **期望行为**：估值维度显式豁免并附一句话理由，豁免项在产物中外显。
* **成功条件**：
  * P0｜估值维度以「显式豁免 + 一句话理由」方式覆盖（如「未上市标的豁免估值维度」）。
  * P0｜豁免项在最终产物中外显，用户与评测可检查。
  * P1｜其余 6 维正常覆盖（独立问题或合并覆盖）。

### F-05 Adapter 偏好问题注入

* **初始状态**：选定 Adapter 的 priority_questions（与第 6 章目录同源）可注入计划生成。
* **期望行为**：对应单元的问题清单包含该 Adapter 的偏好问题。
* **成功条件**：
  * P0｜对应单元问题含 Adapter 偏好问题（来源可追溯到目录）。
  * P1｜偏好问题优先级与其 Adapter 配置一致。

| F-D2 | unit_id 非法拦截 | 引用不存在单元打回 |
| F-D3 | 校验失败 fallback | 重试 2 次后默认计划 + 外显 |
| F-D4 | 计划零投资判断 | 计划不夹带结论 |
| F-D5 | 演进约束 | 变更须引用 question_id + open 上限 |
| F-D6 | P0 数量超限告警 | 超参考上限告警不拦截 |

### F-D1 母框架覆盖校验拦截

* **初始状态**：白盒环境，计划生成 mock 输出缺失「管理层与资本配置」维度的任何处理决定。
* **期望行为**：覆盖校验识别缺失维度，带错误信息打回重生成。
* **成功条件**：
  * P0｜缺失维度的计划未放行（校验打回生效）。
  * P1｜重试后 7 维覆盖完整（独立/合并/豁免均可）。

### F-D2 unit_id 引用非法拦截

* **初始状态**：白盒环境，计划生成 mock 输出某问题 unit_id =「unit_fintech_2」（granularity_decision.units 中不存在）。
* **期望行为**：引用校验拦截该问题，打回重生成。
* **成功条件**：
  * P0｜非法 unit_id 未进入交付计划（拦截生效）。
  * P1｜重试后引用合法。

### F-D3 校验失败 fallback 默认计划

* **初始状态**：白盒环境，计划生成 mock 连续 2 次输出非法计划。
* **期望行为**：重试上限 2 次后 fallback 到 Core Skill + Adapter 推荐问题清单作为默认计划。
* **成功条件**：
  * P0｜重试 2 次后 fallback 默认计划（未无限重试、未静默失败、任务未崩溃）。
  * P0｜fallback 计划外显标注（用户与评测可识别这是默认计划）。
  * P1｜默认计划本身通过基础校验（可执行）。

### F-D4 计划不夹带投资判断

* **初始状态**：正常输入，真实执行计划生成。
* **期望行为**：计划只列「待回答的问题 + 完成标准 + 证据需求」，不含结论。
* **成功条件**：
  * P0｜计划全文不含投资判断类结论性表述（如「茅台具备强护城河」）。
  * P1｜问题描述为可证伪的问题形式，非陈述句结论。
  * P1｜判断性内容仅出现在「决策相关性」等元字段中且指向待验证问题。

### F-D5 计划演进约束生效

* **初始状态**：初始计划已生成并进入研究循环；循环首轮触发计划变更（新增/关闭/降级问题）。
* **期望行为**：每次变更引用 question_id；open 问题数受上限约束。
* **成功条件**：
  * P0｜每次变更引用 question_id（新增/合并/降级/关闭均可追溯）。
  * P1｜open 问题数超上限触发工程告警（兜底生效）。
  * P1｜计划变更记录版本化，可回放。

### F-D6 P0 数量超限告警不拦截

* **初始状态**：白盒环境，计划生成 mock 输出 P0 问题数超参考上限的计划（如 15 条 P0）。
* **期望行为**：超限触发遥测告警，不自动拦截（防计划过大靠告警观察，非硬拦截）。
* **成功条件**：
  * P1｜超限告警存在（未告警即扣分）。
  * P1｜计划正常交付可执行（未被拦截打断）。

## 八、跨环节传导用例（X 类）

| 编号 | 场景 | 验证点 |
| --- | --- | --- |
| X-01 | 四件套端到端串通 | 全链路产物齐备 + 持久化 |
| X-02 | 单一计划传导 | 1 份计划混装多单元问题 |
| X-03 | 全链缓存复用 | 版本未变②③零重复调用 |
| X-04 | 耗时成本观测 | P95 埋点存在（监控项） |
| X-05 | SOTP 传导标记 | split 时估值方法约束传导 |

### X-01 四件套端到端串通

* **初始状态**：current_entity + user_goal 注入，全链路真实执行（或冻结夹具回放）。
* **期望行为**：四环节串行执行完毕，四件套全部产出并持久化。
* **成功条件**：
  * P0｜四件套（company_facts / granularity_decision / per-unit 画像 + 选型 / research_plan）全部产出且结构合法。
  * P0｜四件套写入任务 Context 并随任务状态持久化（跨轮保留可验证）。
  * P1｜facts_version 在四件套间一致（同一任务同一版本）。

### X-02 单一计划传导不复制

* **初始状态**：腾讯 split 三单元场景全链执行。
* **期望行为**：研究计划是 1 份，问题用 level + unit_id 标记归属。
* **成功条件**：
  * P0｜research_plan 仅 1 份，level = company 与 level = segment 混装。
  * P0｜公司级共享问题（如整体资本配置）不按单元复制 N 份。
  * P1｜P0 跨单元统一排序可见。

### X-03 全链缓存复用

* **初始状态**：同任务第二次前处理触发（facts_version 未变），缓存有效。
* **期望行为**：环节①②③全部命中缓存，零重复模型调用。
* **成功条件**：
  * P0｜环节②粒度决策、环节③画像路由全部命中缓存（trace 零模型调用）。
  * P1｜环节①事实包同样命中缓存（无新检索）。
  * P1｜第二次前处理耗时显著低于首次（缓存摊薄可观测）。

### X-04 前处理耗时与成本观测

* **初始状态**：前处理执行，观测埋点开启。
* **期望行为**：四环节合计耗时与模型调用成本按 P95 口径记录。
* **成功条件**：
  * P1｜四环节合计耗时与成本埋点存在（监控项，不设门禁）。
  * P1｜缓存复用率、计划改写幅度两项线上观测指标可采集。

### X-05 SOTP 传导标记

* **初始状态**：腾讯 split 三单元，各单元 Adapter 含 preferred_valuation_methods 配置。
* **期望行为**：mode = split 时估值方法约束传导至下游（研究循环估值维度可识别按单元估值路径）。
* **成功条件**：
  * P0｜SOTP 触发标记传导（mode = split 时下游可识别分单元估值汇总路径）。
  * P1｜各单元估值方法来自其 Adapter 配置（不得临时另选）的约束标记存在。

## 九、执行规范与记录

### 9.1 断言类型

每条用例的成功条件落到三类断言上，评测器按类型采集证据：

| 断言类型 | 采集对象 | 示例 |
| --- | --- | --- |
| 结果断言 | company_facts、granularity_decision、company_profile、selected_adapter、research_plan 等最终字段 | C-01 one_line_business 带溯源；D-01 mode = split 三单元；F-01 7 维覆盖 |
| 行为断言 | trace 中的工具调用序列、校验打回记录、缓存命中记录 | C-05 无新检索调用；D-04 无粒度判断模型调用；E-D1 幻觉 ID 拦截事件 |
| 输出断言 | 结构化字段的完整性与格式 | source_trace 覆盖率；reason 非空且命中差异条件；每题字段完整 |

选型正确性（E-02）与计划问题质量（F-04 等）由预置标准答案 + LLM-as-Judge 结合判定；Judge 不直接裁决 P0（第 8 章原则：能由规则判定的事项不交给 Judge 兜底）。

### 9.2 评测基建需求

* 检索回放夹具：冻结的白名单信源快照，支持正常返回、空返回、冲突返回、失败注入四种模式（支撑 C 类）。
* 结构化数据 mock：financial_snapshot 标准答案（支撑 C-01 / C-02 / C-D4）。
* 年报及公告检索 mock：可用的补足数据源（支撑 C-06）。
* 粒度判断 mock：注入 split / whole / 低置信 / 单单元矛盾等坏输出（支撑 D 类防御）。
* Adapter 目录 mock：目录内/目录外 ID、preferred_valuation_methods 配置（支撑 E 类、X-05）。
* 画像 mock：枚举越界标签、幻觉 ID、低置信标签（支撑 E 类防御）。
* 计划生成 mock：缺维度、非法 unit_id、超限 P0、夹带结论等坏输出（支撑 F 类防御）。
* 认知库预置器：注入三类用户认知条目（支撑 F-02）。
* 版本变更触发器：facts_version v1 → v2 场景（支撑 D-05 / X-03）。
* 重复执行器：同输入连跑 5 次统计一致率（支撑 D-D5 / E-04，pass^k 口径）。
* trace 采集与回放：source_trace、reason、selection_reason、校验打回、缓存命中等全量落盘，供审计与失败归因。
